# Persona Anchors Ablation Protocol

**Pre-registered:** 2026-06-02. Single-variable A/B that adds a "Behavioral Anchors" section to each persona brief (everything else byte-identical to the existing Style A) and tests whether it changes review quality.

## Motivation

The literature synthesis ([`RESEARCH_PERSONA_PROMPTING.md`](RESEARCH_PERSONA_PROMPTING.md)) concluded that the highest-leverage upgrade to a persona brief is **short behavioral anchors** — concrete worked examples showing how the archetype phrases a critique, a refusal, or a tradeoff. Several converging strands support this:

- **Kong et al. NAACL 2024** ("Better Zero-Shot Reasoning with Role-Play Prompting") — large gains came from *what the role does*, not the name.
- **Salewski et al. NeurIPS 2023** ("In-Context Impersonation") — domain match in the role matters; concrete framings transfer better than labels.
- **ExpertPrompting (Xu et al. 2023)** — long, method-rich expert descriptions outperform short labels.
- Practitioner heuristic — "show, don't tell" the persona's voice via 2-4 short examples in the brief.

This is the next-step recommendation that fell out of run #5 (framing A/B). It tests whether **adding** that section produces measurable lift, holding everything else constant.

## Variable isolated

Per persona, a new section `## Behavioral Anchors` is inserted between `## Operating Principles` and `## Problem-Solving Process`. Each anchors section contains 4 vignettes (~3-6 sentences each) covering:
- Critique anchor (how the lens phrases a defect)
- Refusal anchor (how the lens declines)
- Tradeoff anchor (how the lens weighs competing concerns)
- One additional of the strongest type for that persona

The anchors are written in third-person ("the Knuth-style move is to…") so they never invent quotes attributed to the real person — addressing the persona-fabrication risk surfaced in the framing experiment.

Everything else in the brief is byte-identical to `agents/<persona>_agent.md` (which is also what runs in the shipped plugin and what was used in the prior K+H+T runs).

## Substrate

Same 50 PRs as the main and framing runs. Same anonymized + skeptic-framed Claude judge. Same K+H+T crew, same terse-output cap on the blind passes.

## Arms

- **Arm A (baseline)**: K+H+T blind passes with the existing briefs (`agents/{knuth,hickey,torvalds}_agent.md`), consensus synthesis, judged. **Reuses scores from `runs/personas/<task_id>/scores/triple-A.json`** — the same baseline used by run #5.
- **Arm B (treatment)**: K+H+T blind passes with the **anchored** briefs (`prompts/{knuth,hickey,torvalds}_agent_anchored.md`), consensus synthesis, judged. All new generation.

Per PR new work for Arm B: 3 persona passes + 1 synthesis + 1 judge = **5 agents**. 50 PRs × 5 = 250 agents. Sharded into 2 workflows of 25 PRs each (125 agents/shard).

## Hypothesis

- **H_anchors**: Style B (anchored briefs) produces ≥3pp higher mean recall than Style A on a paired sign test (one-sided, α=0.05). The literature is more confident than for the framing experiment, so we pre-commit to the alternative direction here.
- **Falsifies**: Δ recall < 0pp (B underperforms or ties) OR |Δ| < 3pp AND p>0.10.

Secondary measures:
- Mean precision per arm
- Mean fabrication rate per arm
- Mean issues flagged per arm

Of particular interest: does adding more brief content increase fabrication (per the persona-fabrication research) or reduce it (because the anchors model the third-person, non-fabricating voice)?

## Decision rule

| Outcome | Action |
|---|---|
| Style B > Style A (Δ recall ≥ +3pp, p<0.05) | Apply anchors to the bundled plugin briefs (knuth/hickey/torvalds), bump plugin to v0.3.0. Run the same anchor exercise for D/L/P briefs as a follow-up. |
| Style B ≈ Style A (\|Δ\| < 3pp, p>0.10) | Keep existing briefs. Note in CLAUDE.md that anchors were tested with no measurable effect — the briefs are saturated at current detail level. |
| Style B < Style A (Δ recall ≤ −3pp, p<0.05) | Keep existing briefs. Note in CLAUDE.md that adding anchors degraded outputs (likely from the irrelevant-attribute mechanism cited in Principled Personas, even when those attributes are method-anchored). |

## Cost

~250 subagents across 2 sharded workflows. Comparable to run #5.

## Notes on the anchor drafts

Anchors were generated by a 3-agent parallel workflow ([`scripts/persona-anchors-drafting-*.js`](scripts/)). Each agent received the existing persona brief and the constraints: third-person voice, no invented quotes, concrete technical situations, 3-6 sentences per anchor. Output is in `prompts/{knuth,hickey,torvalds}_agent_anchored.md`.

This means the anchors themselves are LLM-generated — they reflect a Claude-mediated view of what each archetype's voice looks like, not a human-curated golden standard. A positive result here would warrant a follow-up with hand-curated anchors to see if the lift comes from anchors-as-such or from anchors-that-happen-to-be-LLM-shaped.
