# Deviations from PROTOCOL.md

## 2026-06-01 — Severity labels not present in substrate

**Original protocol:** Recall of "human-flagged P0+P1 issues."

**Reality:** `foundry-ai/swe-prbench` exposes `human_review_comments` (the verbatim review comments) and a `has_requested_changes` bool, but no per-comment severity labels. All 100 eval_split rows have `severity=None`.

**Adjustment:**
- Primary metric becomes recall of human reviewer-raised issues (any severity), measured at fixed precision 0.70.
- The judge (GPT-5.1 by default) infers severity from the comment text and the PR's `has_requested_changes` flag. Comments on PRs with `has_requested_changes=True` are treated as ≥ P1 by default.
- For comparability with prior SWE-PRBench work, we also report raw recall@all without severity stratification.

**Rationale:** The substrate gives us real human reviewer ground truth, which is the load-bearing signal. Severity inference is a known judging step (used by SWE-PRBench's own baselines per the dataset card). The headline claim shifts from "improves P0/P1 recall" to "improves recall of human-flagged issues" — slightly broader, still measurable, still falsifiable.

## 2026-06-01 — Pilot pool restricted to has_requested_changes=True

**Original protocol:** Stratified random sample of 80 from `eval_split`.

**Reality for pilot only:** 3-PR pilot drawn from the 20 PRs in `eval_split` where `has_requested_changes=True`. This guarantees the pilot's 3 PRs actually have meaningful reviewer-flagged issues to score against (the 80 PRs without requested changes have less ground truth signal per PR).

**Adjustment:** Pilot only — selects 3 PRs with `has_requested_changes=True`, stratified by language where possible. The full 80-PR run uses the stratified sample from the original protocol across all 100 eval rows.

## 2026-06-01 — Language stratification adjusted to substrate distribution

**Original protocol assumed:** 20 Py, 20 JS/TS, 15 Go, 15 Java, 10 Rust/C++.

**Reality:** Substrate has no Rust or C++. Distribution is Python 67%, Go 13%, JS 10%, TS 7%, Java 3% in eval_split.

**Adjustment:** Stratified sample matches natural distribution: Python 55, Go 10, JS 8, TS 5, Java 2 (total 80 out of 100 eval rows).

## 2026-06-01 — Main run scaled to n=50 (Workflow agent cap)

**Original protocol:** 80 PRs stratified.

**Reality:** Each PR consumes 15 subagent slots in the main run (6 personas + 2 syntheses + 2 single-agent baselines + 4 score agents + 1 H3 manipulation-check classifier). The Workflow tool caps lifetime agents at 1000 per workflow; n=80 × 15 = 1200 exceeds the cap. We scaled to n=50 (= 750 agents, well under the cap with headroom).

**Adjustment:**
- `data/prs_main.json` (50 PRs) generated by `select_prs.py --main` with seed=42.
- Same stratified-sample procedure, proportionally scaled: Python 34 / Go 7 / JS 5 / TS 3 / Java 1.
- Statistical power at n=50 with paired sign test: detects effect sizes ≥ ~0.15 in recall-delta at p<0.05 if direction is consistent (sufficient given the pilot's +0.20 mean delta).

## 2026-06-01 — Judge bias-mitigation in main run

**Original protocol:** GPT-5.1 as primary judge; Claude-as-judge forbidden.

**Reality:** No `OPENAI_API_KEY` available; the crew is designed to be invoked inside Claude Code / Codex, so the test environment is Claude-only. Judge remains Claude.

**Mitigations applied** (recorded so future replications can compare):
1. **Anonymized judge prompt** — the judge no longer sees `arm=<name>` or the synthesis's `flagged_by` provenance; each flagged issue is presented stripped of attribution.
2. **Skeptic framing** — judge instructed to default to FABRICATED when uncertain, breaking Claude's mild tendency to charitably interpret Claude-shaped outputs.

These do not eliminate Claude-judging-Claude bias; they reduce its most obvious vectors. The headline H1 (preserved dissent vs consensus, same crew, same passes) is the most robust against this bias because both arms are produced by the same Claude crew — the bias should apply symmetrically.

## 2026-06-01 — H3 manipulation check replaced

**Pilot finding:** Exact-string fingerprint Jaccard gave 1.000 distance across all persona pairs (everything looks disjoint when descriptions are paraphrased).

**Main-run fix:** One LLM classifier per PR receives all 6 persona issue lists and outputs a 6×6 pairwise-similarity matrix where two issues match if they identify the same underlying concern (paraphrase OK). `analyze.py` falls back to the old exact fingerprint if `h3_similarity.json` is missing.

**Caveat:** This is itself a Claude-classifying-Claude step. We accept it as gating-only — H3 is a sanity check that personas diverged, not a headline metric. If H3 reports < 0.30 distance, the experiment is aborted regardless of H1/H2 results.

## 2026-06-05 — H2 token-budget comparison not cleanly validated

**Original protocol:** Arm C is a single Claude agent with extended thinking, hard-capped at the realized median total token count of Arm A. If the token gap exceeds 15%, the H2 comparison is invalid.

**Reality:** The Workflow-driven main run did not capture reliable input/output token accounting for the single-agent arms; materialized metadata records zero token counts for those outputs. The prompt asked the single-agent arm to take extra care, but the run record does not prove a hard token cap or a realized token match within 15%.

**Adjustment:** Treat H2 as an intended extended-thinking single-agent comparator, not as a clean equal-compute result. Do not cite the H2 result as proving or disproving equal-compute superiority. The public empirical claim that survives is the raw-recall sanity comparison against the naive single-agent baseline, plus the process/auditability claim.

## 2026-06-05 — Dataset revision pinned for reruns

**Original protocol:** Load `foundry-ai/swe-prbench` / `eval_split` from HuggingFace.

**Reality:** The scripts originally loaded the dataset without a revision, so future reruns could drift if upstream changed the dataset.

**Adjustment:** Rerun scripts now pin the dataset revision to `b87f5797aef3ed2c3153bb1304ea4d801d36ba6e`. The committed sampled files (`data/prs_pilot.json`, `data/prs_main.json`) remain the files of record for the completed run.
